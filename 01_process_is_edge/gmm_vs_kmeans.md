## 1. K-Means Clustering

### What it is

K-Means is a partitioning algorithm that divides N data points into K clusters
by minimizing the total within-cluster sum of squared distances from each point
to its cluster centroid.

### The algorithm

1. **Initialize**: pick K centroids (randomly, or via K-Means++).
2. **Assign**: assign each point to the nearest centroid (Euclidean distance).
3. **Update**: recompute each centroid as the mean of its assigned points.
4. **Repeat** steps 2-3 until assignments stop changing (or a max iteration
   limit is reached).

This is a coordinate-descent approach that is guaranteed to converge, though
only to a **local** minimum. Running the algorithm multiple times with
different initializations (`n_init`) and keeping the best result is standard
practice.

### Objective function

K-Means minimizes the **inertia** (within-cluster sum of squares):

```
J = sum over all clusters k of: sum over all points x_i in cluster k of: ||x_i - mu_k||^2
```

where `mu_k` is the centroid of cluster k.

### Assumptions

- **Spherical clusters**: K-Means implicitly assumes clusters are roughly
  spherical (isotropic) because it uses Euclidean distance. It cannot capture
  elongated or tilted cluster shapes.
- **Equal variance**: all clusters are assumed to have similar spread. A
  cluster with large variance will "absorb" points from neighboring
  smaller clusters.
- **Equal size (tendency)**: while not a hard constraint, K-Means tends to
  produce clusters of roughly similar size, even when the natural clusters are
  imbalanced.
- **Hard assignment**: every point belongs to exactly one cluster. There is no
  notion of uncertainty — a point on the boundary between two clusters gets
  the same hard label as a point deep inside one cluster.
- **Features must be scaled**: because K-Means relies on Euclidean distance,
  features with larger variance dominate the clustering. **StandardScaler**
  (zero mean, unit variance) should be applied before fitting.

### Strengths

- Simple, fast, and scalable (linear complexity in N).
- Easy to interpret: each cluster is defined by its centroid.
- Works well when clusters are indeed compact and spherical.
- Deterministic (given the same initialization and data).

### Weaknesses

- Cannot capture clusters that are elongated, tilted, or have different shapes.
- Hard assignments provide no measure of uncertainty.
- Sensitive to initialization (mitigated by `n_init`).
- Requires K to be specified in advance.
- No principled model-selection criterion (must rely on external measures like
  silhouette score).

### scikit-learn usage

```python
from sklearn.cluster import KMeans

kmeans = KMeans(n_clusters=4, random_state=42, n_init=10)
labels = kmeans.fit_predict(X_scaled)
```

Key parameters:
- `n_clusters`: number of clusters K.
- `n_init`: number of random restarts (default 10); the run with lowest
  inertia is kept.
- `random_state`: seed for reproducibility.

## 2. Gaussian Mixture Model (GMM)

### What it is

A GMM is a **probabilistic generative model** that assumes the observed data
was generated by a mixture of K multivariate Gaussian (normal) distributions.
Each Gaussian component represents a cluster and is characterized by:

- **Mean vector** (`mu_k`): the center of the cluster.
- **Covariance matrix** (`Sigma_k`): the shape, orientation, and spread of the
  cluster.
- **Mixing weight** (`pi_k`): the prior probability that a randomly drawn
  point came from component k. The weights sum to 1.

The probability density of a data point x under the mixture is:

```
p(x) = sum over k of: pi_k * N(x | mu_k, Sigma_k)
```

where `N(x | mu, Sigma)` is the multivariate Gaussian density.

### The algorithm: Expectation-Maximization (EM)

GMM parameters are estimated via the **EM algorithm**, which alternates between
two steps:

1. **E-step (Expectation)**: for each data point, compute the *responsibility*
   — the posterior probability that the point belongs to each component, given
   the current parameters.

   ```
   r_ik = (pi_k * N(x_i | mu_k, Sigma_k)) / sum_j (pi_j * N(x_i | mu_j, Sigma_j))
   ```

2. **M-step (Maximization)**: update the parameters to maximize the expected
   log-likelihood, using the responsibilities as soft weights.

   ```
   mu_k    = (sum_i r_ik * x_i) / (sum_i r_ik)
   Sigma_k = (sum_i r_ik * (x_i - mu_k)(x_i - mu_k)^T) / (sum_i r_ik)
   pi_k    = (sum_i r_ik) / N
   ```

3. **Repeat** until the log-likelihood converges (changes by less than a
   tolerance) or a max iteration limit is reached.

Like K-Means, EM converges to a **local** optimum, so multiple initializations
(`n_init`) are used.

### Relationship to K-Means

K-Means is a **special case** of GMM where:
- All covariance matrices are constrained to be `sigma^2 * I` (spherical,
  equal variance).
- The responsibilities are forced to be 0 or 1 (hard assignment).
- `sigma -> 0` (the Gaussians become delta functions).

This means GMM strictly generalizes K-Means. Anything K-Means can discover,
GMM can also discover — but GMM can additionally capture structures that
K-Means cannot.

### Covariance types

The shape of each cluster is controlled by the `covariance_type` parameter:

| Type | Shape | Free parameters per component | When to use |
|------|-------|-------------------------------|-------------|
| `"full"` | Arbitrary ellipsoid (different size, shape, orientation) | d*(d+1)/2 | Correlated features (financial data) |
| `"tied"` | Same ellipsoid for all components | d*(d+1)/2 (shared) | Clusters differ only in location |
| `"diag"` | Axis-aligned ellipsoid | d | Uncorrelated features |
| `"spherical"` | Sphere (equivalent to K-Means geometry) | 1 | Isotropic clusters |

where d = number of features.

Both notebooks use `"full"` because financial features (factor returns, macro
indicators) are correlated — a diagonal or spherical constraint would miss the
cross-feature structure.

### Assumptions

- **Data comes from a mixture of Gaussians**: this is the core generative
  assumption. In practice, financial return distributions have heavier tails
  than Gaussian (excess kurtosis). GMM will still find meaningful clusters, but
  the probabilistic interpretation (e.g., "this month has 87% probability of
  being Risk-Off") should be treated as approximate.
- **Components are independent given the mixture**: each data point is drawn
  from exactly one component. The model does not capture temporal dynamics
  (e.g., regime persistence or transition probabilities). For that, a Hidden
  Markov Model (HMM) would be needed.
- **Stationarity within each component**: the mean and covariance of each
  component are fixed. The model cannot capture drift within a regime.
- **Features must be scaled**: same reasoning as K-Means — features with
  larger variance would dominate the likelihood calculations. StandardScaler
  is applied before fitting.

### Strengths

- **Soft assignments**: each point gets a probability vector across clusters.
  This captures uncertainty (e.g., a transition month may have 55% Risk-On /
  45% Risk-Off), which is more informative than a hard label.
- **Flexible cluster shapes**: with `covariance_type="full"`, GMM can capture
  ellipsoidal clusters of any orientation and size. This is critical for
  correlated data.
- **Principled model selection**: BIC and AIC are built into the model
  framework, providing a statistically grounded way to choose K.
- **Generative model**: you can sample new data points from the fitted mixture
  to simulate scenarios.

### Weaknesses

- **More parameters**: `"full"` covariance requires d*(d+1)/2 parameters per
  component. With d=9 factors and K=6 components, the model has 270 covariance
  parameters alone. This can lead to overfitting on small datasets.
- **Singularity risk**: if a component collapses onto a small set of points,
  its covariance matrix can become singular. The `reg_covar` parameter adds a
  small value to the diagonal to prevent this.
- **Slower than K-Means**: EM is more computationally expensive than K-Means,
  though still practical for datasets up to hundreds of thousands of points.
- **Gaussian assumption**: heavy-tailed financial data can violate the
  normality assumption. Clusters driven by extreme events may be poorly
  characterized.

### scikit-learn usage

```python
from sklearn.mixture import GaussianMixture

gmm = GaussianMixture(
    n_components=4,
    covariance_type="full",
    n_init=10,
    reg_covar=1e-6,
    random_state=42
)
gmm.fit(X_scaled)

labels = gmm.predict(X_scaled)          # hard assignment (most probable component)
probs  = gmm.predict_proba(X_scaled)    # soft assignment (responsibility matrix)
bic    = gmm.bic(X_scaled)              # Bayesian Information Criterion
aic    = gmm.aic(X_scaled)              # Akaike Information Criterion
```

Key parameters:
- `n_components`: number of Gaussian components K.
- `covariance_type`: `"full"`, `"tied"`, `"diag"`, or `"spherical"`.
- `n_init`: number of EM restarts; best (highest log-likelihood) is kept.
- `reg_covar`: regularization on the diagonal of covariance matrices.
- `random_state`: seed for reproducibility.

## 3. Head-to-Head Comparison

| Property | K-Means | GMM |
|----------|---------|-----|
| **Model type** | Geometric (distance-based) | Probabilistic (likelihood-based) |
| **Cluster shape** | Spherical only | Arbitrary ellipsoid (`"full"`) |
| **Assignment** | Hard (0 or 1) | Soft (probabilities) |
| **Handles correlated features** | No | Yes (via covariance matrix) |
| **Objective** | Minimize within-cluster sum of squares | Maximize log-likelihood |
| **Algorithm** | Lloyd's iteration (assign + update) | Expectation-Maximization |
| **Convergence** | Local minimum of inertia | Local maximum of log-likelihood |
| **Built-in model selection** | No (use silhouette, elbow) | Yes (BIC, AIC) |
| **Uncertainty quantification** | None | Posterior probabilities per point |
| **Speed** | Faster (O(NKd) per iteration) | Slower (matrix inversions) |
| **Parameters to estimate** | K*d (centroids only) | K*(d + d*(d+1)/2 + 1) for `"full"` |
| **Risk of overfitting** | Lower (fewer parameters) | Higher with `"full"` on small data |
| **Generative** | No | Yes (can sample new points) |

### When to use each

**Use K-Means when**:
- Features are uncorrelated or have been decorrelated (e.g., after PCA).
- You need fast, scalable clustering on very large datasets.
- You want a simple baseline to sanity-check a more complex model.
- Hard assignments are acceptable.

**Use GMM when**:
- Features are correlated (common in finance, economics, biology).
- You need uncertainty estimates on cluster membership.
- You want principled model selection via BIC/AIC.
- Cluster shapes are expected to be non-spherical.

In general, **start with K-Means as a baseline, then fit GMM for a richer
analysis**. If both methods agree on cluster structure, confidence in the
result increases. If they disagree, investigate why — the disagreement itself
is informative.

## 4. Model Selection Criteria

### How to choose K (number of clusters)

Neither K-Means nor GMM determines K automatically. You must sweep over a
range of K values and use selection criteria.

### BIC (Bayesian Information Criterion)

```
BIC = -2 * log_likelihood + k * ln(n)
```

- `k` = number of free parameters in the model.
- `n` = number of data points.
- **Lower is better**.
- BIC approximates `-2 * ln(marginal likelihood)`. The marginal likelihood
  is the probability that the model generated the data, integrated over all
  possible parameter values (Bayesian model evidence). Because of the negative
  sign, lower BIC means higher marginal likelihood — the model is more
  probable.
- BIC is **consistent**: given enough data, it selects the true K if the data
  truly comes from a mixture.
- The `k * ln(n)` penalty grows with sample size, making BIC increasingly
  strict about adding parameters as the dataset grows.
- **Available for**: GMM (built-in via `gmm.bic(X)`). Not available for
  K-Means.

### AIC (Akaike Information Criterion)

```
AIC = -2 * log_likelihood + 2 * k
```

- **Lower is better**.
- AIC minimizes the expected Kullback-Leibler divergence between the fitted
  model and the true data-generating process — i.e., it selects the model
  that best predicts new observations.
- AIC is **efficient**: it may select a more complex model than the "true"
  one, but it minimizes prediction error.
- The penalty `2k` is weaker than BIC's `k * ln(n)` (since `ln(n) > 2` for
  any dataset with n > 7). As a result, AIC tends to favor more complex models
  than BIC.
- **Available for**: GMM (built-in via `gmm.aic(X)`). Not available for
  K-Means.

### When BIC and AIC disagree

This happens frequently. It signals that additional clusters improve fit but
not enough to justify their complexity under BIC's stricter standard. In
practice:

- **Use BIC** when the goal is parsimony, interpretability, and regime
  identification (the case in both notebooks).
- **Use AIC** when the goal is out-of-sample density estimation or
  forecasting, where a slightly more complex model may capture structure that
  BIC would prune away.
- Reporting both exposes the tension between parsimony and fit.

### Silhouette Score

```
s(i) = (b(i) - a(i)) / max(a(i), b(i))
```

- `a(i)` = mean distance from point i to other points in the same cluster.
- `b(i)` = mean distance from point i to points in the nearest other cluster.
- Range: [-1, 1]. Values near 1 mean well-separated clusters; near 0 means
  overlapping; negative means the point is likely in the wrong cluster.
- **Higher is better**.
- **Distance-based** (not model-based), so it applies to both K-Means and GMM.
  However, it evaluates cluster separation in Euclidean space, which aligns
  better with K-Means's objective than GMM's likelihood-based framework.
- Best used as a **sanity check** alongside BIC/AIC, not as the sole criterion.
- **Available for**: both K-Means and GMM (uses hard labels from either).

### Summary

| Criterion | Available for | Lower/Higher is better | Strengths | Limitations |
|-----------|---------------|------------------------|-----------|-------------|
| **BIC** | GMM only | Lower | Principled, penalizes complexity, consistent | Requires likelihood |
| **AIC** | GMM only | Lower | Prediction-oriented, efficient | Tends to overfit (weak penalty) |
| **Silhouette** | Both | Higher | Model-agnostic, intuitive | Euclidean-only, heuristic |

## 5. How They Are Used in This Project

### In `factor_regimes.ipynb`

**Data**: 9 AQR factor return series (1927-2026, ~1,190 monthly observations),
StandardScaler-normalized.

**Workflow**:

1. GMM is fitted for K = 2, 3, 4, 5, 6. For each K, BIC, AIC, and silhouette
   (GMM) are recorded.
2. K-Means is fitted for the same range. Silhouette (K-Means) is recorded.
3. Model selection:
   - Silhouette peaks at K=2 (GMM: 0.288, K-Means: 0.234).
   - BIC is minimized at K=3 (26,366), though K=2 is close (26,391).
   - AIC decreases monotonically, favoring K=6.
4. K=2 is chosen (silhouette-driven, near-minimal BIC) — two regimes labeled
   **Risk-On** and **Risk-Off**.
5. The two-regime labels are validated through a confirmation chain: regime
   labeling, timeline alignment with historical events, volatility analysis,
   factor return decomposition, regime statistics, and duration analysis.

**Role of each model**:
- **GMM**: primary model. Provides the regime labels, soft probabilities, and
  the BIC/AIC grid for model selection.
- **K-Means**: comparison baseline. Confirms that the two-cluster structure is
  not an artifact of GMM — K-Means also peaks at K=2 in silhouette, though
  with lower scores (0.234 vs 0.288), reflecting its inability to capture the
  ellipsoidal cluster shape in the correlated factor space.

### In `macro_regimes.ipynb`

**Data**: 4 FRED macro indicators (2002-2026, ~275 monthly observations),
StandardScaler-normalized.

**Workflow**:

1. **Core analysis** (4 indicators): GMM with K=4 is fitted directly (no grid
   search). K=4 is chosen a priori to match economic narrative (Expansion,
   Recovery, Crisis, Tightening). Silhouette: 0.252.
2. **Extended analysis** (25 indicators): both GMM and K-Means are fitted with
   K=4. Silhouette comparison: GMM 0.417, K-Means 0.448.
3. **PCA + GMM**: PCA reduces the 25 indicators to the principal components
   explaining 95% of variance, then GMM is fitted on the reduced space.
   Silhouette: 0.396.
4. **Hierarchical clustering** (Ward linkage): fitted as a third comparison
   method. Cophenetic correlation: 0.710.
5. Regime labels are validated against S&P 500 realized volatility and
   drawdowns.

**Role of each model**:
- **GMM**: primary model in both core and extended analyses. Provides soft
  probabilities and the regime labels used in all downstream validation.
- **K-Means**: comparison in the extended analysis. Achieves slightly higher
  silhouette (0.448 vs 0.417) because the PCA-decorrelated features better
  satisfy K-Means's spherical assumption, but GMM is still preferred for its
  probabilistic output.
- **Hierarchical**: additional comparison, useful for visualizing the
  dendrogram and assessing cluster stability via cophenetic correlation.
